# RAG на Weaviate

Учебный сервис отвечает на вопросы по локальной базе знаний библиотеки «Харборлайт». Документы режутся на чанки, чанки с эмбеддингами лежат в Weaviate, по вопросу ищутся ближайшие фрагменты, и LLM отвечает только по ним. Если контекст слабый, модель не вызывается.

## Установка

Нужны Python 3.11+, [uv](https://docs.astral.sh/uv/) и Docker.

```bash
uv sync
```

Скопируйте `.env.example` в `.env` и впишите ключ OpenRouter. Ключ не печатается и не пишется в лог.

```text
OPENROUTER_API_KEY=
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
LLM_MODEL=openai/gpt-4o-mini
```

Эмбеддинги считает локальная модель `deepvk/USER2-base`. Если PyTorch видит GPU, расчёт идёт на CUDA, иначе на CPU. Первый запуск скачивает веса.

## Как поднять Weaviate

```bash
docker compose up -d
```

Сервис слушает `localhost:8080` (HTTP) и `localhost:50051` (gRPC). Доступ анонимный, встроенного vectorizer нет: векторы считает приложение. Коллекция — `KnowledgeChunk`.

## Как подготовить базу знаний

Положите текстовые файлы в кодировке UTF-8 в каталог `knowledge_base/`. Один файл — один документ, читаются только `*.txt`. При загрузке перевод строк приводится к `\n`, пробелы и табы внутри строки схлопываются, пустые строки выбрасываются. Пустой после очистки файл пропускается.

Сейчас в базе восемь файлов:

- `opening_hours.txt` — часы работы
- `borrowing_rules.txt` — сроки выдачи и штрафы
- `membership.txt` — карты читателя
- `events.txt` — мероприятия и книжный клуб
- `volunteers.txt` — волонтёры
- `children_section.txt` — детский зал
- `digital_catalog.txt` — электронные книги
- `contact_and_locations.txt` — адреса и телефоны

Проверка без Weaviate и без LLM:

```bash
uv run python main.py
```

Команда печатает имя каждого файла, длину очищенного текста, число чанков и три первых чанка с метаданными.

## Как загрузить чанки в Weaviate

Размер чанка — 800 символов, перекрытие — 150. Окно скользит по символам, соседние чанки делят ровно 150 символов. У каждого чанка есть `document_id`, `source_name`, `chunk_id` (`имя_файла:индекс`) и `text`.

```bash
uv run python main.py ingest
```

Команда заново создаёт коллекцию и записывает все чанки с эмбеддингами. Повторный запуск не копит дубликаты: коллекция удаляется и заполняется заново. В конце печатаются устройство, число объектов и один объект из базы.

## Как задать вопрос

Weaviate должен быть запущен, коллекция — заполнена через `ingest`, в `.env` — ключ OpenRouter.

```bash
uv run python main.py ask "На сколько дней выдают обычные книги?"
```

Команда считает эмбеддинг вопроса той же моделью, что и при загрузке, берёт 5 ближайших чанков и просит модель ответить только по ним. Модели запрещено добавлять факты вне этого контекста.

Если фрагментов нет или ни один `score` не достигает порога 0.57, LLM не вызывается и печатается отказ. Порог сравнивается с близостью, не с дистанцией.

```bash
uv run python main.py ask "На сколько дней выдают обычные книги?" --compare
```

Флаг `--compare` добавляет второй ответ той же модели без документов. Без поиска модель не знает правил этой библиотеки.

## Как читать ответ

Печатаются четыре блока.

- **Ответ** — текст модели или готовый отказ. Строка `source_name` внутри этого текста — цитата самой модели. Сверяйте её со списком ниже: список собирает программа, а не модель.
- **Контекст** — прошёл ли лучший фрагмент порог 0.57 и вызывалась ли модель.
- **Источники** — `source_name` и `chunk_id` каждого чанка, который ушёл в модель. При отказе список пуст (`нет`): слабые фрагменты в промпт не попадают.
- **Фрагменты** — top-5, даже если модель не вызывалась. По ним видно, почему порог прошёл или нет.

`source_name` — файл в `knowledge_base/`. `chunk_id` — этот файл и номер чанка с нуля. `distance` — косинусная дистанция Weaviate: `0` значит, что векторы совпали. `score = 1 - distance`, поэтому большее значение — более близкий фрагмент.

## Оценка поиска

```bash
uv run python eval.py
uv run python eval.py --sweep
uv run python eval.py --top-k 3 --threshold 0.6
uv run python eval.py --chunk-size 400 --overlap 80
```

Команда не вызывает LLM. Она берёт размер чанка, перекрытие, top-k и порог из `config.py` и подменяет их этими флагами. Печатает таблицу по вопросам и итог: Hit@k и MRR отдельно для своих вопросов и для перефразированных, долю ложных отказов по этим двум группам, долю верных отказов на чужих вопросах и долю отказов на пограничных.

`--sweep` один раз ищет каждый вопрос, затем по тем же чанкам строит таблицу порогов от 0.40 до 0.75 с шагом 0.05.

Если размер чанка или перекрытие отличаются от config, скрипт пишет временную коллекцию `KnowledgeChunkEval` и удаляет её в конце. Рабочая коллекция `KnowledgeChunk` остаётся. При настройках из config нужен уже выполненный `ingest`.
