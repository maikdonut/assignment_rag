# RAG на Weaviate

День 1 загружает локальную базу знаний и очищает текст. День 2 режет очищенный текст на чанки. День 3 считает эмбеддинги локальной моделью и складывает чанки в Weaviate. День 4 ищет по вопросу ближайшие чанки. День 5 отвечает на вопрос только по найденным фрагментам. День 6 не вызывает модель, если найденный контекст слабый.

## Установка

```bash
uv sync
```

Эмбеддинги считает `deepvk/USER2-base` с Hugging Face, локально. Если PyTorch видит GPU, расчёт идёт на CUDA, иначе на CPU. Первый запуск скачивает веса модели.

## Weaviate

```bash
docker compose up -d
```

Сервис слушает `localhost:8080` (HTTP) и `localhost:50051` (gRPC). Анонимный доступ, без встроенного vectorizer: векторы считает приложение.

## Список документов и примеры чанков

```bash
uv run python main.py
```

Команда печатает имя каждого файла и длину очищенного текста в символах, затем число чанков и три первых чанка с метаданными.

Размер чанка — 800 символов, перекрытие — 150. Окно скользит по символам: соседние чанки делят ровно 150 символов хвоста и начала.

## Загрузка в Weaviate

```bash
uv run python main.py ingest
```

Команда заново создаёт коллекцию `KnowledgeChunk` и записывает все чанки с эмбеддингами и метаданными (`document_id`, `source_name`, `chunk_id`, `text`). Повторный запуск не копит дубликаты: коллекция удаляется и заполняется заново. В конце печатаются устройство, число объектов и один объект из базы.

## Ответ на вопрос

Нужны переменные в `.env`: `OPENROUTER_API_KEY` и `OPENROUTER_BASE_URL`. Модель по умолчанию — `openai/gpt-4o-mini`. Её можно сменить переменной `LLM_MODEL`.

```bash
uv run python main.py ask "На сколько дней выдают обычные книги?"
```

Команда считает эмбеддинг вопроса той же моделью, что и при загрузке, берёт из Weaviate 5 ближайших чанков и просит LLM ответить только по ним. Модели запрещено добавлять факты вне этого контекста. Если фрагментов нет или ни один не дотягивает до порога релевантности 0.57, LLM не вызывается и печатается отказ. Порог сравнивается с `score`: это близость, не дистанция.

Печатаются ответ, список источников (`source_name` и `chunk_id` каждого переданного чанка), затем сами фрагменты: `score`, `distance` и начало текста.

`distance` — косинусная дистанция Weaviate: `0` значит, что векторы совпали. `score = 1 - distance`, поэтому большее значение — более близкий фрагмент. `source_name` — файл базы знаний, из которого взят чанк.

```bash
uv run python main.py ask "На сколько дней выдают обычные книги?" --compare
```

Флаг `--compare` добавляет второй ответ той же модели без документов. Его удобно сверить с ответом по контексту: без поиска модель не знает правил этой библиотеки.

## Оценка поиска

```bash
uv run python eval.py
uv run python eval.py --sweep
uv run python eval.py --top-k 3 --threshold 0.6
uv run python eval.py --chunk-size 400 --overlap 80
```

Команда не вызывает LLM. Она берёт `chunk_size`, `overlap`, `top_k` и порог из `config.py` и подменяет их этими флагами. Печатает таблицу по вопросам и итог: Hit@k и MRR отдельно для своих вопросов и для перефразированных, долю ложных отказов по этим двум группам, долю верных отказов на чужих вопросах и долю отказов на пограничных. Плохие метрики не меняют код выхода.

`--sweep` один раз ищет каждый вопрос, затем по тем же чанкам строит таблицу порогов от 0.40 до 0.75 с шагом 0.05.

Если размер чанка или перекрытие отличаются от config, скрипт нарезает базу заново, считает эмбеддинги и пишет временную коллекцию `KnowledgeChunkEval`. Перед этим и в конце прогона коллекция удаляется. Рабочая коллекция `KnowledgeChunk` остаётся. При настройках из config нужен уже выполненный `ingest`.
